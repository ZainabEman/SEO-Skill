# Run sequence

1. Validate inputs. Resolve the repository and run `.venv/bin/python .agents/skills/seo-growth-strategy/scripts/preflight.py URL --market DE/de` with optional `--profile`, `--language`, repeatable `--competitor` and `--pdf`. Record the printed run path. Use `--resume PATH` for a compatible checkpoint and `--refresh` for a new public crawl within that run.
2. Inspect the public sample for offerings, audience, geography, page types, navigational paths, evidence of trust and CTAs. Use `technical_seo.audit` as an initial candidate list. Review status and redirect chains, robots rules, sitemap coverage, indexability directives, language, canonicals, headings, links, schema indicators and alt attributes. Verify a bounded sample of priority CTA destinations with a GET and inspect interaction in an authorized browser when useful. Never submit an enquiry. Where a route is approved and demonstrably free, collect bounded field performance/PageSpeed measurements. Otherwise disclose unavailable.
3. Discover competitor candidates using user input, confirmed zero-credit OpenSEO project context and public search for evidenced offerings and market. Fetch a bounded first-party website sample for each selected candidate using `Crawler.crawl` and save the evidence. Score and compare as specified in [competitor selection](competitor-selection.md).
4. Resolve OpenSEO project by exact domain in the connected project list. Check recent research and use correctly scoped cached evidence where possible. When first-party routes are authorized, check zero-credit property discovery for the matching project and read performance only after confirming exact scope and zero-credit status or appropriate approval. Follow [data sources](data-sources.md) and [cost controls](cost-controls.md) before provider calls. Save results and their collection timestamps with the run and key cache records by account, exact tool and parameters. Record errors, missing fields and partial coverage. Never retry a metered call without reconciling the previous attempt.
5. Build dated findings, a keyword map, and a prioritized roadmap. Connect actions to specific observed findings. Use [prioritisation](prioritisation.md) and [report template](report-template.md).
6. Write `report.json` and `sources.json` and run `.venv/bin/python PATH/scripts/render_report.py RUN_DIR OUTPUT_DIR` with `--pdf` when requested. Inspect the resulting documents and the validation file. Share a verified download route and summarize unavailable datasets.
